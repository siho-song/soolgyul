# 술 카탈로그 출처 정책

## 목적과 범위

카탈로그는 국내에서 수입되거나 제조·판매된다는 근거가 확인되는 술의 데이터다.
이 정책은 출처 등록, 수집 허용 조건, 원문 보존과 정본 승격 조건을 정한다.

수집하지 않는 것: 가격, 판매처, 재고, 구매 링크, 판매점 리뷰 원문, 무단 복제 콘텐츠.
제품 이미지는 출처와 권리 상태가 등록된 출처에서 별도 이미지로만 모은다.
정본 단위는 판매 SKU가 아니라 병 안의 술이다(`docs/specs/ALCOHOL_CATALOG_DATA_CONTRACT.md`).

## 출처 우선순위

1. 정부·공공기관 또는 권리자가 제공하는 구조화 API·공개 파일
2. 제조사·수입사와 사용 범위를 합의한 공식 제휴 피드
3. 이용조건과 robots 검토가 모두 끝난 제조사·수입사 공식 HTML
4. 정부기관 공식 제품 사진 갤러리, 수입사가 직접 등록·관리하는 검토된 업계 카탈로그
5. 위 출처에 이미지가 없을 때에 한해, 검수한 주류 전문 판매점의 자사 단일 상품 페이지 또는 자사 상품 피드
6. 운영자가 공식 원문과 대조해 승인한 보완 정보

- 낮은 우선순위 출처는 높은 우선순위 사실을 덮어쓰지 못한다. 충돌은 별도 주장으로 보존하고 검수 대상으로 보낸다.
- 판매점은 제품 사실의 우선 출처가 아니다. 제품 식별, 시장 관찰과 이미지 대체 출처로만 쓴다.
- 검색 엔진은 원본 상품 페이지를 찾는 용도로만 쓴다. 검색 결과 썸네일과 프록시 URL은 저장하지 않는다.
- 오픈마켓 개별 판매자, 사용자 업로드, 리뷰, SNS와 원본 페이지를 확인할 수 없는 이미지는 쓰지 않는다.

## 출처 등록 조건

모든 출처는 제공기관, 원본 URL, 수집 방식, 허용 필드, 원문 보존 가능 여부, 출처 표기, 갱신 주기,
요청 한도, 약관·robots 확인 시각, 라이선스 검수 상태를 기록한다.

- `approved`: 허용 필드와 이용 조건이 확인되어 수집할 수 있다.
- `candidate`: 발견만 했다. 수집, 원문 보존, 정본 발행은 금지한다.
- `rejected`: 정책이나 권리 조건과 맞지 않아 쓰지 않는다.
- 라이선스 검수가 끝나지 않은 출처는 `approved`가 될 수 없다.
- HTML 출처는 약관 확인 시각과 robots 확인 시각이 모두 있고 라이선스 검수가 승인되어야 `approved`가 된다.
- robots가 수집을 막는 출처는 거절한다. 검색으로 찾은 후보와 이미지도 쓰지 않는다.
- 공개 열람이 가능하다는 사실만으로 자동 수집 권리가 생기지 않는다. robots와 이용조건은 서로를 대신하지 못하며, 하나라도 불명확하면 `candidate`로 둔다.
- `candidate` 공식 사이트는 robots 허용 범위에서 출처 URL, 제품 식별용 목록명, 상세 위치, 이미지 위치, 본문 체크섬까지만 기록한다. 이미지 바이트와 장문 본문은 저장하지 않는다.

## 이미지 출처

프로젝트 소유자가 `owner_assumed`로 승인한 공식 제조사·수입사 출처, 정부기관 공식 사진 갤러리,
수입사 회원 등록형 업계 카탈로그는 이미지 바이트를 모아 쓸 수 있다. `owner_assumed`는 출처별 서면
이용허락이 아니라, 소유자가 공식 상품 이미지의 사용 위험을 인수한 예외다. 조건은 모두 지킨다.

1. 판매점·마켓플레이스·검색 결과·SNS가 아니라 공식 페이지, 정부 갤러리, 검토된 업계 카탈로그여야 한다.
2. robots 제한과 기술적 접근 제한을 우회하지 않는다.
3. 출처 URL, 상세 페이지, 내용 해시, 확인일, 출처 표기를 보존한다.
4. 장문 소개 원문은 별도 허락 없이 복제하지 않는다.
5. 권리자 요청이나 컴플레인이 오면 즉시 비공개하고 주종별 기본 이미지로 바꾼다.

위 출처에서 이미지를 못 찾은 제품은 지역과 무관하게 검증된 주류 전문 판매점의 자사 상품 페이지나
공개 상품 피드를 대체 출처로 쓸 수 있다. 해외 도메인이라는 이유만으로 제외하거나 승인하지 않는다.

1. 출처 등록부에 `source_class=verified_retailer`, `rights_status=owner_assumed`로 개별 등록한다.
   DB 출처 기록에는 `retailer`로 명시적으로 옮기며, 다른 값으로 뭉개지 않는다.
2. 병 안의 술 정체성이 높은 신뢰도로 일치하는 결과만 연결한다. 용량 차이는 무시하고, 빈티지·숙성연수·캐스크 피니시·edition·batch처럼 술을 가르는 값은 유지한다.
3. 가격, 재고, 판매처, 구매 링크, 사용자 리뷰, 편집 설명은 저장하지 않는다.
4. 실제 상품 페이지와 원본 이미지 URL을 근거로 남긴다.
5. 공개 사이트맵·상품 API를 먼저 쓰고 robots, 로그인, CAPTCHA, 요청 한도를 우회하지 않는다.
6. 전용잔·선물 세트, 다병 묶음, 구형·신형 포장 상품은 후보에서 뺀다. `전용잔 미포함`처럼 단일 병임을 밝히는 문구는 제외 사유가 아니다.
7. 이름 정규화나 다국어 별칭 검색으로 찾은 후보도 같은 관문을 거친다. 출처 등록이나 robots 확인이 안 된 이미지는 운영 카탈로그로 올리지 않는다.
8. 같은 내용 해시가 여러 제품에 걸리면 중복·오매칭 검토를 마친 뒤 대표 이미지를 정한다.

## 여러 출처의 제품 정본화

공급자 제품 행과 술결 정본 제품은 분리한다. 허용된 공급자 행은 출처 키와 공급자 제품 ID로 각각 보존하며,
정본 제품 하나에 여러 출처 행이 연결될 수 있다.

- 정확한 문자열 일치에 실패한 행도 지우지 않고 신규 제품 또는 중복 검토 후보로 둔다.
- 공통 식별 근거는 한글명, 영문명, 생산자·브랜드, 국가, 주종이다. 와인·위스키·사케·전통주는 생산자·지역·release 식별값을 더 비교한다.
- 판정은 자동 병합, 검토 후보, 별개로 나누고 일치 근거와 결정적 충돌을 함께 보존한다.
- 용량, 케이스, 전용잔·선물세트, 패키지는 식별 근거에 넣지 않는다.
- 빈티지, 숙성연수, 캐스크·피니시, 원액·레시피, edition, batch가 충돌하면 자동 병합하지 않는다.
- 누적 카탈로그 행이나 판매점 관찰만으로 현재 판매 중이라고 확정하지 않는다.
- 검증 판매점 행에서 허용하는 필드는 제품명, 영문명, 브랜드·생산자, 주종, 국가, 공급자 제품 ID, 상세 위치, 이미지 위치, 관찰 시각이다.
- 판매점 분류는 정확히 하나의 공급자 ID로 이어진 제품에 한해 약한 분류 후보가 될 수 있다. 이름 유사도만으로 연결하지 않고, 검수 전에는 공개하지 않는다.
- 판매점의 리뷰, 시음 노트, 소개 문구는 수집하지 않고 감각 사실이나 이야기로 올리지 않는다.
- 판매점 분류가 공식·공공 출처와 충돌하면 자동으로 승자를 고르지 않고 원문과 사유를 검수 대기열에 남긴다.
- 감각 수치는 그 제품의 것만 쓴다. 다른 에디션이나 빈티지의 값을 끌어오지 않고, 빈티지가 섞인 출처는 정확한 빈티지로 나눈 뒤에만 쓴다.
- 사용자가 기록한 감각은 카탈로그 값과 달라도 고치지 않는다. 카탈로그는 설명의 근거일 뿐 사용자 경험의 정답이 아니다.

## 허용 사실과 원문 보존

구조화 출처의 제품명, 공식 생산자명, 국가·지역, 주종, 원료, 제조·숙성 방식, 공식 도수, 검증 가능한 공식 향미는
필드 단위 주장으로 모을 수 있다. 모든 주장은 출처, 원본 ID·URL, 확인 시각, 신뢰도, 검수 상태로 거슬러 갈 수 있어야 한다.

- 원문 구간을 보존하더라도 자동으로 정본이 되지 않는다. 모두 비공개 상태에서 검수한다.
- 제품에만 정확히 연결되고 release가 정해지지 않은 행은 release 검토 전에 공개 사실로 올리지 않는다.
- 주장 승인만으로 공개하지 않는다. 문서 권리, 출처 라이선스, 권리 검수, 출처 활성 상태를 함께 확인하고, 이 중 하나가 무너지면 공개를 거둔다.
- 승인된 주장과 그 근거 문서는 제자리에서 고치지 않는다. 바뀐 내용은 새 출처·새 문서로 만든다. 라이선스·권리·약관 검토 시각과 활성 상태만 운영 상태로 갱신한다.
- 긴 제품 소개, 생산자 이야기, 감각 서술은 라이선스가 허용해도 자동으로 이야기가 되지 않는다. 사실 단위로 나눠 사람이 원문과 대조해 검수한다. 권리를 확인하지 못한 서술은 체크섬과 출처 위치만 남기고 본문을 보존하지 않는다.
- `raw_preservation_allowed=true`는 비공개 영역에 원문을 보관해도 된다는 뜻이지 공개 API로 노출한다는 뜻이 아니다. 원문은 서비스 관리 영역에만 두고 보존기간, 접근제어, 삭제 절차를 적용한다.
- API 인증키는 등록부, URL, 로그, 근거 자료에 저장하지 않고 실행 시점의 비밀 저장소에서만 주입한다.

## 값을 찾지 못했을 때

찾을 수 없는 사실은 비워 둔다. 도수, 감각 단계, 분류처럼 수집할 수 있는 값을 추정하지 않는다.
외부 출처의 분류는 원문 그대로 근거로 보존한 뒤 매핑 검수를 거쳐 분류 체계에 잇는다.
애매한 분류는 비워 두거나 검수 상태로 남기며 가장 가까운 분류나 `other`에 넣지 않는다.

## 분류 체계

주종·스타일·다축 분류·원료·공정·이야기 주제의 정본은 하나의 사전 `catalog/dictionary/terms.json`이고,
구형 소비자용 부분집합은 `config/catalog/taxonomy.json`이다. 새 주종과 스타일은 데이터와 등록부를 함께 바꾸며,
앱·API·DB 코드의 enum만 고쳐서 늘리지 않는다. 사전 값은 검증기를 통과한 생성 시드로만 반영하고 수동 SQL로 추가하지 않는다.
시드는 덧붙이기 전용이다. 용어·별칭을 끄거나 의미를 바꿀 때는 영향받는 공개 관계를 먼저 조회하고
철회·갱신 대기열을 만든 뒤 별도 마이그레이션으로 적용한다.

## 재검수

출처의 URL, 약관, 라이선스, robots, 응답 구조, 요청 한도, 제공기관이 바뀌면 자동 수집을 멈추고 다시 검수한다.
공공 출처는 최소 연 1회, HTML은 수집 실행 전과 조건 변경 감지 시 검수한다.
승인되지 않은 출처의 데이터는 운영 카탈로그로 올리지 않는다.

## 이미지 파생본

- 원본의 출처 URL, 출처 키, 내용 해시, 권리·검수 정보는 저장소와 로컬 보관 파일에 보존한다. 공개 버킷에는 제품당 대표 이미지 한 장만 둔다.
- 공개 이미지는 512x640(4:5) WebP, 품질 80이다. 원본 비율을 유지해 가운데에 안전 여백과 함께 놓고, 늘이기·강제 자르기·병목이나 라벨 절단을 허용하지 않는다.
- 투명 정보가 있는 이미지는 투명도를 유지한다. 불투명 원본은 술결 중립 배경 RGB(247, 239, 230) 위에 놓는다.
- 저해상도 원본은 비율을 깨거나 임의로 선명하게 만들지 않고 품질 경고로 표시한다.
- 자동 배경 제거가 병, 잔, 투명 액체, 라벨 경계를 해치면 원본 파생본을 쓴다. 원본을 덮어쓰지 않는다.
- 이미지는 출처 권리, 제품 식별, 파일 무결성의 자동 관문을 통과하면 공개한다. 오매칭 문의가 오면 해당 이미지를 먼저 비공개하거나 기본 이미지로 바꾼 뒤 고친다.
- 이미지가 없거나 안전하게 식별되지 않은 제품도 기록과 취향카드 생성을 막지 않는다.
