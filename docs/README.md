# 술결 문서 안내

이 파일이 문서의 시작점이다. 제품의 현재 상태는 아래 정본 문서에서 읽고, 과거 이력은
Git에서 본다.

## 먼저 읽을 문서

| 궁금한 것 | 문서 | 역할 |
|---|---|---|
| 무엇을 만드는가 | [PRD](PRD.md) | 현재 제품 범위와 제외 범위 |
| 무엇을 결정했는가 | [ADR](ADR.md) | 지금 참인 제품 결정과 그 이유 |
| 시스템이 어떻게 나뉘는가 | [Architecture](ARCHITECTURE.md) | 구성 요소, 데이터 흐름과 경계 |
| 데이터는 어떻게 저장되는가 | [Database](DATABASE.md) | 테이블 역할, serving 경계와 변경 규칙 |

PRD는 제품이 무엇을 하는지, ADR은 왜 그렇게 정했는지를 말한다. 둘 다 현재형이다. 결정이
바뀌면 두 문서의 해당 문장을 고쳐 쓰고, 이력은 Git에서 본다.

## 운영 문서

- `catalog/`: 구현에 필요한 카탈로그 계약과 원천 정책
- `security/`: 테스트가 직접 검증하는 인증, RLS, 탈퇴·보존과 제외 범위 계약

완료된 작업 로그와 일회성 import·검수 evidence는 별도 문서로 보존하지 않는다. 현재
상태는 위 정본 문서와 최종 manifest에서 확인하고, 과거 실행 과정은 Git 이력에서 찾는다.
원본·복구 JSON/CSV와 DB migration은 남긴다. 이를 요약한 중복 진행 보고서는 별도로 유지하지 않는다.

## 문서 추가·정리 원칙

1. 새 파일을 만들기 전에 위 표의 기존 소유 문서에 넣을 수 있는지 먼저 확인한다.
2. 일회성 진행률과 작업 로그를 새 Markdown으로 만들지 않는다. 반복 생성 값은 JSON
   데이터 파일에 갱신하고, 사람이 읽을 현황은 기존 문서 한 곳에만 둔다.
3. 같은 개념의 초안이 여러 개면 현재 내용만 하나의 문서로 합치고 과거 초안은 삭제한다.
   Git 이력이 복구 경로다.
4. ADR은 대안이 있었고, 되돌리기 비싸고, 코드만으로는 이유를 알 수 없는 제품 결정만
   남긴다. 바뀌면 그 항목을 고쳐 쓰고, 더는 참이 아니면 지운다. 에이전트는 기록할지
   묻기만 하고, 사용자가 예라고 할 때만 쓴다.
5. 완료된 작업의 중복 설명은 제거하되 원본·복구 자료나 실행 도구가 읽는 입력은 임의로 삭제하지 않는다.
