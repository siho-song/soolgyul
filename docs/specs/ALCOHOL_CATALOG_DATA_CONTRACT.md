# 술 카탈로그 데이터 계약

테이블 역할과 컬럼은 `docs/DATABASE.md`가, 수집 출처 규칙은 `docs/catalog/SOURCE_POLICY.md`가 소유한다.
이 문서는 카탈로그에 무엇이 한 항목인지, 무엇을 모으는지, 무엇을 공개하는지만 정한다.

## 1. 목적

카탈로그는 검색, 기록 보조, 제품 이미지, 감각 정보가 함께 쓰는 제품 기반이다.
수집 원문을 그대로 공개하지 않고, 출처와 검증 상태가 분명한 값만 앱에 내보낸다.

## 2. 한 항목의 단위

카탈로그 항목은 판매 SKU가 아니라 병 안의 술이다.

| 단위 | 의미 | 포함하지 않는 것 |
|---|---|---|
| Product | 용량과 판매처가 달라도 같은 술인 제품 | 세트 상품, 잔 포함 패키지, 단순 용량 차이 |
| Media | 제품에 연결된 이미지 한 장의 Storage 경로 | 원본 파일 자체를 DB에 저장하는 것 |

같은 이름이라도 실제 제품이 다르면 합치지 않는다. 용량, 전용잔 세트, 포장만 다른 상품은 별도 제품이 아니다.
세트·패키지·edition은 단어가 아니라 내용물로 판정한다.

| 판매 표기 | 처리 |
|---|---|
| 여러 종류의 술이 든 세트 | 단일 제품이 아니므로 제외 |
| 같은 술 여러 병, 잔·사은품 포함 패키지 | 기본 제품 하나로 모으고 중복 행 삭제 |
| 라벨·아트·띠·협업·기념 포장 edition | 같은 내용물이고 기본 제품 근거가 있으면 기본 제품으로 모은다 |
| 캐스크·피니시·원료·블렌드가 다른 edition | 별도 제품 |
| 판정 근거가 부족한 edition | 자동 병합하지 않고 별도 제품 |
| 단일 술을 식별할 수 없는 세트·패키지 | 공개하지 않고 제외 |

제품명 끝에 `세트` 같은 음절이 있다는 이유만으로 제거하지 않는다. 독립된 판매 표기일 때만 처리한다.

## 3. 저장소와 공개의 경계

- 저장소는 원문, 수집 상태, 근거와 재처리 자료를 보존한다.
- 공개 DB는 앱이 조회할 검증된 값만 가진다.
- 수집, 정규화, DB 적재와 공개는 서로 분리한다. 새 데이터는 자동으로 공개되지 않는다.
- 원천이 없거나 실패한 값은 비워 두거나 수집 상태로 남긴다. 이름이나 주종에서 추정해 채우지 않는다.
- 앱은 원문 자료를 직접 읽지 않고 공개용 조회면만 쓴다.

## 4. 제품 규칙

- `name_ko`와 `name_en`은 앱이 그대로 보여 주는 시장 상품명이다. 출처 코드, 용량, 포장·사은품 문구를 뺀다.
- 생산자는 관계로 따로 찾을 수 있게 두되, 표시명을 생산자 필드에서 기계적으로 합성하지 않는다.
- 도수가 제품 라인을 가르는 상품(예: 화요 17)은 도수별 제품으로 둔다. 그 밖의 도수는 도수 필드에 둔다.
- 용량은 저장하지 않는다.
- `style_key`는 근거로 확인되는 사용자용 계열 하나다. 원료·공정·숙성·당도처럼 함께 성립하는 특성은 각각의 키로 두고 `style_key`에 합치지 않는다.
- 판정 근거가 없는 계열은 비워 둔다. 가장 가까운 계열이나 `other`로 넣지 않는다.
- 릴리스 단위는 따로 없다. 빈티지·연산·edition·batch로 구분되는 변형은 각각 별도 제품 행이다. 용량, 가격, 판매처, 포장 구성만으로 행을 나누지 않는다.

## 5. 감각 정보

- 사용자 체감과 공식·카탈로그 노트는 별개다. 서술(descriptor)과 수치 강도를 섞지 않는다.
- 직접 출처, 언어, 대상 제품과 관측 시점을 추적한다.
- 편집자 추정값을 제품 사실처럼 공개하지 않는다.
- 누락은 낮음이나 0이 아니라 모름이다. 감각 키는 `docs/specs/SENSORY_CATALOG.md`를 따른다.

## 6. 이미지

- 제품당 이미지는 한 장이다. 순위나 대체 연결을 두지 않는다. 출처와 권리 기록은 로컬 보관 파일에 둔다.
- 잘못된 이미지는 연결을 바꾸거나 게시를 멈춘다. 다른 제품에 재사용하지 않는다.
- 공개 조회면은 내부 저장 경로 대신 허용된 URL만 준다.

## 7. 수집과 정규화

출처 우선순위와 허용 사실은 `docs/catalog/SOURCE_POLICY.md`, 도구는 `tools/catalog/` 아래에 있다.

- 수집은 재시작할 수 있어야 하고, 실패와 실제 정보 없음을 구분한다.
- 이름 표기, 언어, 괄호·용량·세트 문구를 정규화하되 원문은 보존한다.
- 모호한 후보는 자동 병합하지 않는다. 생산자·도수·실제품이 다른 동명이품은 표시명이 같아도 합치지 않는다.
- 가격, 재고, 판매처, 구매 URL은 제공하지 않는다.
- 같은 입력으로 다시 돌리면 결과가 같아야 한다.

### 7.1 주종별 수집 필드

모든 주종이 같은 필드를 모으지 않는다. 카드가 그 주종의 맛과 질감을 설명할 때 실제로 쓰는
필드만 모으고, 스타일이나 법이 이미 정해 주는 공정은 병마다 모으지 않는다.

| 주종 | 모으는 필드 | 모으지 않는 필드(이유) |
|---|---|---|
| 위스키 | 통 종류, 캐스크 피니시·더블 캐스크, 피트, 숙성 연수(없으면 NAS로 확인), 캐스크 스트렝스, 냉각 여과 여부 | 증류 방식(스타일이 정함) |
| 와인 | 품종, 산지, 빈티지, 오크 숙성 여부, 스파클링 방식 | 숙성 연수(빈티지로 대신함) |
| 사케 | 정미율, 등급, 살균, 원주, 니고리, 일본주도·산도 | 통(다루 사케만 예외) |
| 전통주 | 종류, 원료, 누룩, 살균 여부, 증류식 소주의 상압·감압 증류 | 통 |

## 8. 공개 읽기와 권한

- 익명·로그인 사용자는 공개된 조회면만 읽는다.
- 적재 중, 보류, 거절 행과 내부 근거는 서버 전용이다.
- 카탈로그 쓰기는 관리자 화면만 믿지 않고 서버 역할과 DB 정책으로 제한한다.
- 적재가 실패하면 일부만 공개하지 않는다. 기존 값과 충돌하는 새 값은 덮어쓰지 않고 보류한다.
- 사용자 탈퇴는 공용 카탈로그, 이미지, 편집 콘텐츠를 지우지 않는다.
