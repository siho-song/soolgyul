# 술결카드 콘텐츠 가이드

술결카드 문안을 작성하고 검수하는 기준이다. 대표 시나리오 20개는 `supabase/functions/_tests/card_*_test.ts`가 실행하며, 문장 구조 규칙의 일부는 `supabase/functions/_shared/taste_card/card_writing.ts`와 `card_prose_effects.ts`가 정한다. 이 문서는 코드와 테스트가 지키지 못하는 기준만 담는다. 제품 요구는 [PRD](../PRD.md)를 따른다.

## 1. 좋은 카드가 답해야 하는 세 질문

술결카드 한 장을 읽은 사용자는 세 가지를 분명히 알 수 있어야 한다.

1. **이번 기록에서 새로 알게 된 취향은 무엇인가?**
2. **이 술을 왜 그렇게 느꼈는가?**
3. **다음에는 무엇을 유지하고 무엇을 바꿔 골라야 하는가?**

사용자가 고른 답을 다시 나열하거나, 제품 설명만 옮겨 적거나, `아직 알 수 없어요`로 끝나면 실패다. 첫 기록도 답변과 제품 정보를 연결해 새 취향 기준과 다음 행동을 제공해야 한다.

## 2. 사용자 화면 순서

```text
상품 → 술결 한입(별명 · 핵심 요약 · 다음 술 가이드) → 전환 문구 → 왜 잘 맞았을까요 → 왜 부담이었을까요 → 저장·공유
(맛이 모두 적당했어요인 균형 기록: 상품 → 술결 한입 → 전환 문구 → 왜 편안했을까요 → 저장·공유)
```

| 영역 | 사용자가 얻는 답 | 피할 내용 |
|---|---|---|
| 상품 | 지금 어떤 술의 기록인가 | 비슷한 상품이나 다른 릴리스의 정보 |
| 술결 한입 | 별명, 이번 한 잔에서 알게 된 내 취향과 그 이유, 다음에 실제로 무엇을 고르면 되는가 | 답변을 줄여 쓴 요약, `비슷한 술을 마셔보세요` 같은 막연한 조언 |
| 전환 문구 | 고정 문구 `조금 더 자세히 알아볼까요?` 한 번 | 버튼이나 접기 조작처럼 보이는 표현, 개인화 |
| 왜 잘 맞았을까요 | 좋았다고 답한 감각마다 왜 그렇게 느꼈는가 | 핵심 요약을 문장만 바꿔 반복, 제품 특성 나열, 당연한 상식 |
| 왜 부담이었을까요 | 부담스러웠다고 답한 감각마다 왜 그렇게 느꼈는가 | 독자의 답을 부정하기, 앞 설명의 반복 |
| 왜 편안했을까요 | 적당했다고 답한 맛마다 그 술의 실제 수치에 견주어 내 입맛의 기준점이 어디인가 | 수치 없는 맛에 대한 설명, 좋았다는 말로 바꿔 쓰기 |
| 저장·공유 | 결과를 남기거나 다시 보는 방법 | 새 분석 문장 |

- 별도 상단 제목(`나의 첫 술결` 등)과 별도 마무리 문단은 두지 않는다. 상세 분석은 처음부터 펼쳐 보여 준다.
- 잘 맞은 답이 없으면 왜 잘 맞았을까요를, 부담이 없으면 왜 부담이었을까요를 제목까지 생략한다. 수를 맞추려고 비슷한 말을 늘리지 않는다. 둘 다 없고 맛이 모두 적당했으면 왜 편안했을까요만 쓰고, 핵심 요약과 가이드도 균형을 기준으로 쓴다.
- 각 주장은 한 영역에서만 설명하고, 다른 영역에서는 연결에 필요한 최소 재언급만 한다.

## 4. 문장 쓰는 기준

술결카드는 사용자를 평가하는 보고서가 아니라 이번 한 잔을 함께 돌아보는 대화처럼 읽혀야 한다.

- `당신은`보다 `이번 한 잔`, `이번 기록`을 중심에 둔다. 서비스가 직접 마신 것처럼 말하지 않고, 사용자가 남긴 반응과 새 해석을 구분한다.
- 직접 확인된 반응은 분명하게 쓰고, 새 해석에만 필요한 만큼 여지를 둔다. 모든 문장에 `가능성이 있어요`를 붙이지 않는다.
- `확인됩니다`, `핵심 경계`, `선호 축` 같은 분석 용어를 쓰지 않는다.
- 한 문장에는 한 가지 중심 내용만 담는다. 반응, 해석, 이유, 다음 행동이 겹치면 나눈다.
- 짧은 문장보다 한 번에 이해되는 문장이 먼저다. 뜻이 모호해지는 주어와 목적어는 빼지 않는다.
- `그 느낌`, `이 기준`처럼 대상을 대신하는 말만 쓰지 않고 감각 이름을 다시 쓴다. 같은 감각은 같은 이름으로 이어 간다.
- `A가 아니라 B`로 비교할 때는 무엇을 비교하는지 먼저 밝힌다.
- 전문 용어는 바로 뒤에서 몸으로 느끼는 말로 푼다. 예: 수렴감은 `혀와 잇몸이 마르고 조이는 느낌`.
- 수식어와 중복 강조는 덜되, 이해에 필요한 연결어와 설명은 줄이지 않는다.
- 마지막 추천은 명령형보다 제안형으로 쓴다.
- 사용자가 답하지 않은 감각을 느꼈다고 지어내거나, 매 카드에 같은 성향·칭찬을 붙이지 않는다.
- 사용자의 반응을 틀렸다고 느끼게 하지 않는다. 전문가가 장점으로 보는 특징도 이 사용자에게는 다를 수 있다고 쓴다.
- 미응답을 중립·불호·못 느낌으로 바꾸지 않는다. 좋았던 쪽만 있으면 부담을, 아쉬웠던 쪽만 있으면 좋아한 감각을 만들어 채우지 않는다.
- 제품에 없는 향을 사용자가 골랐으면 그 경험을 보존하고, 제품의 다른 특징으로 바꿔 쓰지 않는다.
- 제품의 1~5 대표값은 측정값이 아니다. 단맛 1을 당분 0으로, 수렴감 점수를 타닌 함량으로 읽지 않는다.
- 함께 나타난 수치만으로 원인을 단정하지 않는다. 한 번의 아쉬움을 주종 전체나 모든 강도의 불호로 넓히지 않는다.
- 감각의 세기와 지속 시간을 구분한다. 전체 여운 길이를 특정 맛이나 말림의 지속 시간으로 대신 쓰지 않는다.
- `다시 마시고 싶다`는 답을 모든 감각의 긍정으로 바꾸지 않는다.

| 피할 문장 | 더 나은 방향 |
|---|---|
| 당신은 과실 향을 좋아해요. | 이번 와인에서는 잘 익은 붉은 과실 향에 좋은 반응을 보였어요. 다른 향에 묻히지 않고 또렷하게 느껴진 점이 마음에 들었던 것으로 보여요. |
| 이번 기록만으로 떫은맛을 싫어한다고 할 수 없어요. | 과실 향과 산미는 마음에 들었지만 입안이 마르는 느낌은 부담이었어요. 다음에는 타닌이 더 부드러운 와인을 골라보세요. |

## 7. 승인 기준

| 판정 | 통과 조건 |
|---|---|
| 화면 순서 | 2절의 순서를 지키고, 고정 문구가 정해진 위치에 한 번씩만 있다. |
| 술결 한입 | 답변 반복을 넘어 제품 정보와 반응에서 도출한 새 취향 기준, 그 이유, 다음 선택 방향이 있다. |
| 이유 문단 | 왜 잘 맞았을까요와 왜 부담이었을까요의 문단마다 핵심 요약에 없던 지식·비유·감각 구분을 더하고 이번 반응에 다시 연결한다. |
| 실사용 | 가이드에 라벨이나 메뉴판에서 그대로 찾을 수 있는 말이 있다. |
| 근거 | 제품과 모든 핵심 문장을 추적할 수 있고 근거보다 넓게 일반화하지 않는다. |
| 반복 | 각 주장은 한 영역에서만 설명한다. |
| 한국어 | 4절의 기준을 지켜 쉬운 구어체로 한 번에 읽힌다. |

모든 판정을 통과하고 사용자가 전체 문안을 직접 승인해야 완성이다. 자동 검사는 고정 문구와 구조의 누락을 막는 보조 수단이며, 새 인사이트의 가치와 한국어의 자연스러움은 사람이 검수한다.
